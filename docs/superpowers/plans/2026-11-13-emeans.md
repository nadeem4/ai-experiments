# e-means vs k-means: implementation plan

**Goal:** Build and run the `emeans` experiment: does e-means reproduce its "Lloyd quality in 1.2-3 epochs" claim on a laptop CPU (A), does warm-started e-means keep a growing vector-search index fresh more cheaply than rebuilding (B, headline), and does its advantage change with embedding dimension (C). Publish as the story page `/emeans`.

**Architecture:** A new `emeans/` folder mirroring `rerank/`: `README.md` (protocol, committed before any run), `RESULTS.md` (after), harness modules, `tests/`, committed `results/`, gitignored `runs/`, `figures.py`. One resumable JSONL record per unit of work. Parts A and C share one race runner (`race.py`); B has its own month-by-month runner (`growing.py`). Registered in `cli` so `uv run cli run emeans --part a|b|c --tag pilot|full` works. The arXiv-CS embeddings come from a Kaggle notebook (`emeans/kaggle/`) via the existing `cli submit` path; everything timed runs on the laptop CPU.

**Tech Stack:** Python 3.12 via uv; `faiss-cpu>=1.16` (`faiss.Kmeans`, `IndexIVFFlat`, `faiss.contrib.e_means.NumpyEmeans`); scikit-learn (`MiniBatchKMeans`); `threadpoolctl`, `psutil`, `h5py`, numpy; matplotlib (existing); `sentence-transformers` (existing) on Kaggle only; Next.js 16 site in `site/` (vitest).

**Spec:** `docs/superpowers/specs/2026-11-13-emeans-design.md` (source of truth; this plan copies its values).

**Planned against** branch `chore/remove-old-experiments` (removes banking77 and typed_decisions; merged first). After it, `cli.EXPERIMENTS == ("rerank",)` and `tests/test_cli.py` asserts `{"rerank"}`. This plan's PRs branch from `main` after that merge. ## Global Constraints

- k = 4,096 for every part.
- SIFT1M: 1M x 128, L2, ann-benchmarks HDF5 (`sift-128-euclidean.hdf5`), 10k queries with true neighbours.
- arXiv-CS: Cornell arXiv metadata (Kaggle, CC0), `cs.*` primary category, January 2018 to December 2025, uniform sample of up to 10,000 abstracts per month (spec says about 960k docs; see Ambiguity 1).
- Embedding: `nomic-embed-text-v1.5`, 768-d, prefix `search_document:`, Kaggle GPU once, not timed; stored float32, unit-normalised, with publish month; model revision, sampling seed and per-month counts go in `DATASET.md`.
- C truncates to d in {64, 128, 256, 512, 768} and re-normalises.
- Split: one fixed split, seed 0 per dataset; 100k vectors held out as the MSE test set, train on the rest. SIFT: IVF index holds all base vectors. arXiv: 10k queries drawn from the 100k test set, index holds every doc except those queries, exact top-10 computed by us.
- All timing on CPU, float32, threads = physical cores, identical for every arm and recorded; timing covers training (plus re-assignment in B) only, via `perf_counter`.
- Arms A: Lloyd = `faiss.Kmeans`, `max_points_per_centroid` raised to cover every training vector, seeded random init; e-means = `NumpyEmeans` defaults (`batch_law="auto"`); MiniBatchKMeans = `init="random"`-style init, `n_init=1`, default batch size and reassignment, `max_no_improvement=None`, `tol=0`, threads pinned with `threadpoolctl`.
- Epochs-to-match: Lloyd test-MSE at iterations {1, 2, 3, 5, 10, 25} from one snapshotting run per seed; Lloyd timing from a separate uninterrupted 25-iteration run; e-means and MiniBatch at {1, 2, 3, 5} epochs, each its own run. "Matches" = mean paired MSE ratio over seeds <= 1.000; none within 5 epochs = "did not match within 5 epochs", no speedup reported.
- Fixed wall-clock budgets 10 s, 30 s, 60 s, 120 s; actual time reported next to the budget; overshoot > 10% flagged.
- 5 seeds per arm x setting in A; 3 seeds in B and C. Seeds vary only initialisation and batch/shuffle order.
- Search: `IndexIVFFlat` per centroid set (centroids as-is, all vectors added), `nprobe` in {1, 4, 16, 64}; recall@10, vectors scanned per query (mean and p95), queries per second (batch search after one warm-up pass).
- B: initial index = 2018-2019 Lloyd-25 centroids; 72 months 2020-01 to 2025-12 arrive one at a time; 500 docs per month held out as queries, never indexed, never in any training pass; arms Stale / Yearly rebuild (every January, Lloyd-25 from scratch, then re-assign all) / Monthly e-means (warm start via `begin(n, init_centroids)`, 0.5 epoch over all indexed docs, seeded shuffle, `finalize`, re-assign all) / Monthly Lloyd same rows (one Lloyd iteration warm-started over a seeded random half of indexed docs, re-assign all).
- B per month per arm: recall@10 at `nprobe` 16 and 64 against exact top-10 over everything indexed so far; vectors scanned (mean, p95); imbalance; dead clusters (< 10 points); maintenance CPU seconds that month and cumulative. Stale maintenance = 0; adding new docs is reported separately, excluded from comparisons.
- B judged by paired per-query bootstrap over 2025's 6,000 queries x 3 seeds; month curves show mean and range across seeds.
- Pilot first: SIFT1M 100k subset, k = 256, one seed, plus three months of the B timeline; checks Lloyd train MSE never rises, `nprobe = k` gives recall 1.0, records complete, warm-started e-means runs through `begin`; then projects full-run wall clock per part. Full runs start only after the projection is approved.
- Record: faiss, scikit-learn, numpy, sentence-transformers versions; embedding model revision; CPU model; thread count; commit; date.

**Repo rules (every slice):** never add Claude or Claude Code attribution to commits, PRs, docs or code; no Notion links in PRs; never tune any arm or threshold on the test set (defaults only); resumable JSONL keyed per unit of work; figures generated only from `results/`; small fast tests on synthetic data, no test downloads a dataset; TDD (failing test first); never edit a README protocol section once a run started (amendments appended, dated).

## Review Focus (failure modes the tests must pin)

1. **Unfair timing / budgets.** Threads pinned and recorded the same for every arm; budget settings derived from a full-scale calibration, overshoot > 10% flagged, never silently clipped. (E2.2, E2.3)
2. **Query leakage in B and A.** A held-out query is never in an index, a training pass, a rebuild or the initial index. (E1.3, E4.1)
3. **Invalid warm start.** Arms 3 and 4 start from the given centroids (not a cold init), touch the same number of rows (within one batch), and e-means subsampling via `max_points_per_centroid` never silently leaves rows out (no label -1). (E4.2)
4. **Ledger inconsistency.** Maintenance = training + re-assignment for every arm, Stale = 0, adding new docs excluded for every arm; cumulative sums only from the per-month records. (E4.3)
5. **Wrong match rule / stats.** "Matches" uses the paired per-seed MSE ratio mean <= 1.000, unmatched reports no speedup, B end-state uses the paired per-query bootstrap, not an unpaired comparison. (E2.4, E4.5)

## Shared names and types (used consistently across slices)

- `Unit = (part, dataset, arm, setting, seed)`, all str except seed int. In B, `setting` is the month `"YYYY-MM"`. The record key is exactly this tuple. Settings strings: `"epochs=3"`, `"iters=25"`, `"budget=30s"`, `"snapshots"`, `"calibration"`.
- `Split` NamedTuple: `train, test, index, queries` float32 arrays, `truth` int64 `(nq, 10)` indexing into `index`.
- `Trained` NamedTuple: `centroids` float32 `(k, d)`, `seconds: float`, `rows: int` (rows touched by training).
- Record fields: `part, dataset, arm, setting, seed, centroids_hash, train_seconds, epochs, rows, test_mse, imbalance, dead_clusters, search` where `search = {nprobe: {"recall10", "scanned_mean", "scanned_p95", "qps"}}`; B adds `assign_seconds, maintenance_seconds, recall_per_query`.
- `K = 4096`, `NPROBES = (1, 4, 16, 64)`, `B_NPROBES = (16, 64)`, `BUDGETS_S = (10, 30, 60, 120)`, `EPOCHS = (1, 2, 3, 5)`, `LLOYD_AT = (1, 2, 3, 5, 10, 25)`, `DIMS = (64, 128, 256, 512, 768)`.
- Scale constants in `experiment.py`: `PILOT = Scale(n=100_000, n_test=10_000, n_queries=1_000, k=256, seeds=1, b_months=3)` and `FULL = Scale(n=None, n_test=100_000, n_queries=10_000, k=4096, seeds=5, b_months=72)`. `--tag pilot` means PILOT, any other tag FULL. (No extra flag.)

## Spec ambiguities decided here

1. **Corpus size.** The spec says up to 10,000 abstracts per month gives about 960k docs and about 240k initial docs; real cs monthly volumes are lower in early years. The plan treats 10,000 as a cap, records real per-month counts in `DATASET.md`, and adds a human gate after the Kaggle fetch. All "per centroid" figures in the spec are approximate.
2. **Pilot cannot set budgets.** A 100k/k=256 pilot does not predict full-scale seconds per epoch, so budgets come from a one-epoch **calibration** per arm at full scale (stored as records), assuming linear time in epochs.
3. **Same init for all arms.** Each seed's `random_init` feeds Lloyd, e-means and MiniBatch (pairs the arms per seed; e-means' default init is also random rows).
4. **Search evaluated only for `iters=25` and budget units** (the indexes a practitioner would build), not every epoch setting, to bound cost.
5. **Publish month** = month of the first version's `created` date; primary category = first listed category.
6. **Yearly rebuild** includes 2020-01 (six rebuilds), maintain-then-measure each month for all arms.
7. **End-state bootstrap**: resample the 6,000 queries (2025, 12 x 500), per-query difference averaged over seeds.
8. **Per-query recall stored in B records** (needed for the paired bootstrap).
9. **Reuse of `rerank`**: `mean_ci` and figure styling constants are imported from `rerank`, not copied.
10. **PR template**: the repo has none, so `~/.claude/templates/pull_request.md` is used.
